# Contract: コマンドライン `can-log-analysis`

## 呼び出し

```text
can-log-analysis PROJECT [--analysis KIND]... [--output-dir DIR]
python -m can_log_analysis PROJECT [--analysis KIND]... [--output-dir DIR]
```

| 引数 | 必須 | 説明 |
|---|---|---|
| PROJECT | ○ | .canprj のパス。解析するログは `PROJECT + ".log.csv"`（FR-001） |
| `--analysis KIND`, `-a KIND` | | `all`（既定）、`latency`、`busload`、`txwait`、`jitter`。複数回指定できる。`all` が 1 つでもあれば 4 つすべて |
| `--output-dir DIR`, `-o DIR` | | 指定すると表ごとに `DIR/<kind>.csv` に書く（DIR がなければ作る。同名ファイルは上書き）。指定しなければ標準出力 |
| `--quiet`, `-q` | | 進捗を出さない（エラーメッセージは出す） |
| `--help`, `-h` | | 使い方を出す |

- 出力する表の順は、指定の順に関係なく latency → busload → txwait → jitter（MFC の「解析」メニューの順）。
- 表の形式は [table-csv.md](table-csv.md)。

## 出力と終了コード

| 状況 | 標準出力 | 標準エラー（UTF-8、1 行） | 終了コード |
|---|---|---|---|
| 成功、`-o` なし | 表 CSV（表の間は空行 1 行） | なし | 0 |
| 成功、`-o` あり | なし | なし | 0 |
| PROJECT がない | なし | `プロジェクトファイルがありません: <PROJECT>` | 1 |
| PROJECT が INI として読めない | なし | `プロジェクトファイルを読めません: <PROJECT>: <理由>` | 1 |
| ログがない | なし | `プロジェクト「<名前>」のシミュレーションログはありません。` | 1 |
| ログが読めない | なし | `<ログのパス>: <MFC と同じ英文>`（例 `…\x.canprj.log.csv: line 5: bad number`） | 1 |
| 出力先に書けない | なし | `出力できません: <パス>: <理由>` | 1 |
| 引数の誤り | なし | argparse の使い方とエラー | 2 |
| Ctrl+C で中止 | なし | `中断しました。` | 130 |

- ログが読めないとき・中止したときは、1 つの表も出さない（途中まで書いたファイルも残さない。すべて計算してから書き出す）。
- 標準出力・標準エラーは常に UTF-8（research R-7）。
- 上の表の「標準エラー」はエラーメッセージの行。0.5 秒を超えた処理では、その前に進捗の行が出ることがある（下記）。

## 進捗（spec FR-042〜FR-044、research R-12）

- 開始（引数を解析し終えた時点）から 0.5 秒を超えても終わっていないときだけ、標準エラーに出す。`--quiet` なら出さない。
- 読み込み中: `ログを読み込んでいます... N%`。N = 読んだバイト数 × 100 // 全体のバイト数（全体 0 なら 100）。
  `read_log_records` の `progress` が呼ばれるたびに、N が前回出した値と違うときだけ出す。
- 読み込みが終わったら（0.5 秒を超えていれば）`集計しています...` を 1 回出す。
- 標準エラーが端末（`isatty()`）なら行頭復帰（`\r`）で同じ行を上書きし、終わるとき（成功・失敗・中止）に改行してから次を出す。
  端末でなければ 1 回ごとに 1 行（LF）で出す。
- 進捗は標準出力・出力ファイルには決して書かない。
- Ctrl+C（`KeyboardInterrupt`）は読み込み中・計算中・書き出し前のどこで起きても受け止め、`中断しました。` を出して 130 で終わる。
  書き出し前に起きればファイルは 1 つもできない。
