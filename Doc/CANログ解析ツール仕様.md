## 1. 目的とスコープ

- **AR-001** CANシミュレータ（MFC版）が出力したフレームログを読み込み、送信待ち時間、受信完了時間、送信ジッタ、CANバス負荷を解析して表とグラフで表示する。**[決定]**
- **AR-002** MFC 版の解析機能（機能028、029）を Python に移植する。MFC 版を正解とし、同じログから同じ数値が出ることを合格条件とする。式・集計の単位・丸め・並び順は MFC 版に合わせ、この文書と MFC 版が食い違うときは MFC 版を優先する。**[決定]**
- **AR-003** 通信速度・ノード数は決め打ちしない。なお MFC 版の4つの解析はログだけから計算し、.canprj の通信速度・周期は使わない（周期はログの送信要求の間隔から求める。AR-043）。.canprj はログの場所とプロジェクト名を決めるために使う（AR-020）。**[決定] [MFC]**
- **AR-004** MFC 版と同じ「解析」メニュー（送信待ち時間、受信完了時間、送信ジッタ、CANバス負荷）を持つデスクトップアプリとする（第5章）。**[決定]**
- **AR-005** 対象は CAN 2.0A（11ビットID）のデータフレーム。**[シミュ仕様 1.3]**
- スコープ外（初期版）: シミュレーションの実行、フレーム編集、エラーフレームの解析、MFC 版にない指標（Rx_Process を使う総送信レイテンシ、ログの Bus_Load_Pct との比較など）。

## 2. 入力

### 2.1 プロジェクトファイル .canprj [MFC ProjectFile.cpp SaveProject]

- **AR-020** 「ファイル > プロジェクトを開く」で .canprj を選ぶ。解析するログは、プロジェクトファイルのパスに「.log.csv」を足したファイルとする（例: sample.canprj → sample.canprj.log.csv）。**[MFC LogFileIndex.cpp LogPathFor]**
- **AR-021** .canprj は UTF-8 の INI 形式。解析で使うのはファイル名（画面タイトル用）だけだが、読み込みは次の形式に従う。

  ```
  ; CAN bus simulator project file (.canprj)
  [Project]
  EcuCount=6
  DurationSec=10
  FrameDisplay=1
  Speed=...
  [Network]
  BitRateBps=500000
  [Node1]
  NodeId=1
  Name=...
  Label=...            (任意)
  RxFilter=0x080,0x100 (任意。なければ全受信)
  ReceiveDelayUs=...
  PowerOnTimeUs=...
  InitDurationUs=...
  [Node1.Frame1]
  Name=...
  CanId=0x100
  Dlc=8
  PeriodUs=10000
  InitialOffsetUs=0
  ```

- **AR-022** プロジェクトを開いていない、またはログがないときは、解析を実行せず理由をメッセージで出す（MFC の IDS_LOG_NONE_NOPROJECT、IDS_LOG_NONE と同じ扱い）。**[MFC]**

### 2.2 フレームログ <プロジェクト>.canprj.log.csv [MFC ReadLogRecords]

- **AR-030** CSV（UTF-8、1行目がヘッダ）。1フレーム×受信ノードで1行。行末の CR は無視、空行は飛ばす。
- **AR-031** 使う列は次の8つ。列はヘッダの名前で探し、順番は問わない。1つでもなければエラー「line 1: no column <名前>」。

  | 列 | 読み方 | 空欄のとき |
  |---|---|---|
  | CAN_ID | "0x" で始まる16進 | エラー |
  | Tx_Node | 整数 | 0 |
  | Rx_Node | 整数 | 0（受信ノードなし） |
  | Tx_Request | 整数 µs | −1 |
  | Tx_Start | 整数 µs | −1 |
  | Tx_End | 整数 µs | −1 |
  | Rx_End | 整数 µs | −1 |
  | Status | SUCCESS、ARBITRATION_LOST_RETRY、OVERWRITE のどれか | エラー |

- **AR-032** 値が読めない行があれば、その行番号付きのエラー（"line N: bad CAN_ID" / "bad number" / "bad Status" / "too few columns"）で読み込みを止める。**[MFC]**
- **AR-033** 大きなログ（数百万行）に備え、読み込みと計算は別スレッドで行う。0.5秒を超えたら進捗バー付きの「解析中」ウィンドウを出し、「中止」で止められるようにする。進捗は読み込み中はバイト数の割合、計算中は満了表示。**[MFC CAnalysisProgressDlg]**

## 3. 共通の前処理

- **AR-040** 1回の送信（トランスミッション）は (Tx_Node, CAN_ID, Tx_Start) で識別し、受信ノードの数だけ並ぶ行を1回にまとめる。**[MFC CollectTransmissions、AnalyzeBusLoad]**
- **AR-041** Status = OVERWRITE の行は計算に使わず、行数を「捨てたフレーム数」として数える（送信待ち時間・受信完了時間の画面に表示）。**[MFC]**
- **AR-042** 統計量は件数、最小、平均、最大、P95。P95 は最近順位法で、昇順に並べた値の ceil(0.95 × n) 番目（整数演算 (n × 95 + 99) ÷ 100）。件数0なら全部0。**[MFC ComputeStats]**
- **AR-043** ヒストグラム: ビン数の目安 = clamp(ceil(√n), 10, 50)。ビン幅 = (最大 − 最小) ÷ 目安 以上で最小の 1・2・5 × 10^m（1 µs 以上）。左端 = 最小値をビン幅で切り捨て（負の値も floor）。ビン i は [左端 + i×幅, 左端 + (i+1)×幅)。全部同じ値なら幅1のビン1本。**[MFC MakeHistogram]**

## 4. 解析の定義 [MFC LogAnalysis.cpp]

### 4.1 受信完了時間 [AnalyzeLatency]

- **AR-050** 受信完了時間 = Rx_End − Tx_Request。対象は OVERWRITE でなく、Rx_Node > 0 で、Rx_End と Tx_Request がある行（受信ノードごとに1件）。
- **AR-051** 表の行: 1行目「全体」、続いて (送信ECU, 受信ECU) の組を昇順に。列は 送信ECU、受信ECU、件数、最小、平均（小数1桁）、最大、P95（µs）。
- **AR-052** 選んだ行の値のヒストグラムを表示する（横軸 µs、縦軸 件数）。表の下の注記に OVERWRITE で捨てた行数を出す。

### 4.2 送信待ち時間 [AnalyzeTxWait]

- **AR-060** 送信待ち時間 = Tx_Start − Tx_Request。AR-040 でまとめた1回の送信につき1件。Tx_Request と Tx_Start がない行は除く。
- **AR-061** 表の行: 1行目「全体」、続いて CAN ID の昇順（各 ID に送信ECU を併記）。列は CAN ID（0x%03X）、送信ECU、件数、最小、平均（小数1桁）、最大、P95（µs）。
- **AR-062** 選んだ行のヒストグラムと、OVERWRITE で捨てた行数の注記を出す（受信完了時間と同じ形）。

### 4.3 送信ジッタ [AnalyzeJitter]

- **AR-070** CAN ID ごとに送信を Tx_Start 順に並べ、k 番目について ジッタ = (Tx_Start[k] − Tx_Start[k−1]) − (Tx_Request[k] − Tx_Request[k−1]) とする（＋は遅れ、−は早まり）。設定上の周期ではなく送信要求の間隔を基準にするので、バッファ満杯で捨てられた送信があっても、その分はジッタに数えない。
- **AR-071** 周期 = 送信要求の間隔のうち最も多い値（同数なら小さいほう）。ms で表示し、整数 ms なら整数、そうでなければ小数3桁。
- **AR-072** 表の行: CAN ID の昇順。列は CAN ID、送信ECU、周期（ms）、件数（= 送信回数 − 1）、最小、最大（µs）、標準偏差（母標準偏差、小数1桁）。1回しか送信していない ID は件数0で、周期以降は空欄。
- **AR-073** 選んだ ID のジッタを時系列で表示する（横軸 Tx_Start の ms、縦軸 µs、0 の線付き、点を線で結ぶ）。点が画面の横ピクセル数より多いときは、列ごとに最小〜最大を縦線で描き、山も谷も消さない。**[MFC CAnalysisGraph Deviation、MinMaxPerColumn]**

### 4.4 CANバス負荷 [AnalyzeBusLoad]

- **AR-080** AR-040 でまとめた送信（OVERWRITE でなく Tx_End > Tx_Start のもの）について、バスは [Tx_Start, Tx_End) の間使用中とする。
- **AR-081** 区間は 10 ms 固定。範囲は 0 から、最後の Tx_End を含む区間の終わりまで（範囲 = ceil(最後の Tx_End ÷ 10 ms) × 10 ms、送信がなければ 10 ms）。区間をまたぐ送信は、またいだ時間をそれぞれの区間に振り分ける。
- **AR-082** 区間ごとの負荷率 = 区間内の使用時間 ÷ 10 ms × 100。平均 = 全使用時間 ÷ 範囲 × 100。最大 = 区間の負荷率の最大と、それが最初に現れた区間。
- **AR-083** ECU ごと（送信したノードだけ、ノード番号順）に、送信回数と使用率（その ECU の使用時間 ÷ 範囲 × 100、小数1桁）を表に出す。
- **AR-084** 画面: 上に要約1行（平均%、最大%、最大の区間 [開始ms, 終了ms]、範囲ms）、中央に区間ごとの負荷率の折れ線（縦軸 0〜100%、平均を破線と値で表示。区間数が横ピクセル数より多いときは列ごとの最大値）、下に ECU 別の表。**[MFC CBusLoadDlg]**

## 5. 画面とメニュー [MFC AnalysisDlg.cpp、MFCApplication1Dlg.cpp]

- **AR-090** メニュー: 「ファイル」（プロジェクトを開く、終了）、「解析」（受信完了時間、CANバス負荷、送信待ち時間、送信ジッタ）。表示名と並び順は MFC 版のリソースに合わせる。**[要確認 AQ-6]**
- **AR-091** 各解析はモードレスの別ウィンドウで開く。同じ解析がすでに開いていれば、新しく作らずそのウィンドウを前面に出す。Esc と閉じるボタンで閉じ、Enter では閉じない。
- **AR-092** ウィンドウタイトルにプロジェクト名を入れる。初期サイズは受信完了時間・送信待ち時間・送信ジッタが 900×640、バス負荷が 960×680、最小 520×400（96 dpi 換算）。所有ウィンドウの中央に出し、モニタの作業領域からはみ出さない。
- **AR-093** 受信完了時間・送信待ち時間・送信ジッタの画面: 上 40% に表、1行の注記、下にグラフ。開いたときは表の1行目を選び、そのグラフを出す。データがない行は「データなし」の表示。**[MFC LayoutListNoteGraph]**
- **AR-094** 数値の書式: 時間は µs の整数、平均と標準偏差と % は小数1桁、ECU は「ECU 01」形式、CAN ID は「0x080」形式。
- **AR-095** 集計処理は画面に依存させない（MFC の LogAnalysis が MFC に依存しないのと同じ構成）。テストと一括処理用にコマンドラインからも同じ関数を呼べるようにする。**[既定]**
- 想定ライブラリ: Python 3.11 以上、PySide6（画面）、pandas または標準ライブラリ（ログ読み込み）、numpy、matplotlib（グラフ）、pytest / pytest-qt。**[既定]**
